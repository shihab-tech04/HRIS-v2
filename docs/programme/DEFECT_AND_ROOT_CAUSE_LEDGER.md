# Defect and Root-Cause Ledger

| Defect / risk | Root cause evidence | Correction in checkpoint | Remaining proof |
|---|---|---|---|
| Authenticated admin route showed a generic record explorer | `LiveSystemWorkspace` route did not represent the supported HRIS modules and existing design architecture. | Replaced route with permission-gated `LiveHrisWorkspace` using observed RPCs. | Compare actual authenticated role screens against approved Figma and existing design shell; test roles in browser. |
| Rich employee summary RPCs reject ordinary linked employees | Production `employee_for_auth_user()` requires an active `admin_users` row and matches the fixed active `synesis-it` tenant. Both summary RPCs call that helper. Read-only inspection also confirmed own-row policies for `employees`, `leave_requests`, and `leave_types` through the separate `hris_own_employee_for_tenant(uuid)` helper; attendance and leave-balance policies still use the admin-only resolver. | Client routing stays constrained to the verified active-admin/Synesis-employee RPC contract. Other linked employees remain on the existing limited RLS-backed leave view. | Define a least-privilege ordinary employee summary contract; isolate-test identity, tenant boundaries, duplicate employee links, attendance, and balances before wiring it. |
| Direct holiday reads can cross tenant boundaries | Production `holidays_read` permits active rows but has no `tenant_id` predicate. The existing leave UI uses tenant-filtered RPCs. | No direct holiday table query is used by the new HRIS workspace. | Test and review a tenant-scoped restrictive policy in isolation before considering any production SQL change. |
| Legacy admin table reads are not tenant-isolated across the full schema | Read-only production review found 20 tenant-keyed tables with authenticated `SELECT` grants and a permissive `has_permission(...)` branch lacking tenant scope; the permission helper resolves global role assignments. Holidays and notices also allow active rows. | The current workspace limits legacy admin UI to `synesis-it` and uses tenant-scoped RPCs for these modules; this is a client-path constraint, not a database fix. | Reconcile accepted tenant-role behavior, then isolate-test tenant-aware RLS for each table and associated definer RPC before multi-tenant acceptance. Do not add blanket policies without preserving approved own-row behavior. |
| Supabase security advisor findings are not fully classified | 2026-10-12 advisor reports 207 authenticated-executable SECURITY DEFINER functions, one anon Candidate jobs function, 24 RLS-enabled tables without policies, and leaked-password protection disabled. | Confirmed the 24 no-policy tables have no anon/authenticated SELECT grants. Candidate jobs function backs the current public jobs view and masks unpublished salary. No function revocations or Auth changes were made. | Function-by-function auth/tenant review, Candidate public-column review, and Auth setting decision with password-flow testing. See `docs/programme/SUPABASE_SECURITY_ADVISOR_20261012.md`. |
| Duplicate Admin View entry | Conflicting route/navigation path in the authenticated admin flow. | Removed duplicate route from `LiveApp`. | Verify navigation across all authorized roles. |
| Unsupported/global dashboard values could leak into tenant summary | Dashboard RPC includes a global candidate count. | Count is not rendered; unsupported values remain unavailable. | Validate tenant data and role behavior in authenticated tests. |
| Approval functions could resolve a pending record without tenant predicate | Read-only inspection of current production function definitions. | Tenant-scoped replacements staged outside production migrations. | Isolated cross-tenant, concurrency, audit and prior-record tests; no production apply yet. |
